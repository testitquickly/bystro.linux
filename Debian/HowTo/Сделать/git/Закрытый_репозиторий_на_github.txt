====== Закрытый репозиторий на github ======

[ @git ]

Ситуация: мой аккаунт входит в закрытую Organization на github. Там создан репозиторий. Надо в него коммитить.

===== Сделать ключ ssh =====

Ключи бывают двух типов:

* Authenication — для коммитов в репозитории
* Signing — для логина на github

Шифрование: ''ed25519''

Можно сразу сделать ключ в профиле github: https://github.com/settings/ssh/new

Можно сделать его на своей стороне ([[Software:ssh]]), затем оставить персональный на своем ноуте и добавить public key в профиль github — https://github.com/settings/keys

Так или иначе, ssh-ключ для аутентификации из собственного аккаунта будет работать и для своих репозиториев, и для репозиториев из организаций, в которые вхож персональный аккаунт. 

===== Настроить распознавание ключей ssh =====

В норме для каждого репозитория надо указать свой ssh-ключ аутентификации. 

В каталоге с репозиторием отредактировать файл ''.git/config'' и там отредактировать строку 

''[remote "origin"]''
	''sshkey = ПОЛНЫЙ_ПУТЬ_К_ПЕРСОНАЛЬНОМУ_КЛЮЧУ''

В SourceGit ключ ssh можно указать в описании репозитория: правый клик по Dashboards > REMOTES > origin 

В [[Software:SmartGit]] этот же файл откроется, если переключиться на нужный репозиторий, затем в верхнем меню пройти по Repository > Edit Git Config > Repository > Edit. В поле “SSH Private Key” указать ''ПОЛНЫЙ_ПУТЬ_К_ПЕРСОНАЛЬНОМУ_КЛЮЧУ''.

А ещё в SmartGit запрос на ssh-ключ должен появиться при первой синхронизации склонированного репозитория, но то такое.

И не факт, что это сработает. Для работы с репозиториями лучше не умничать и сразу редактировать 

''mcedit ~/.ssh/config''

В этом файле для каждого источника надо добавить отдельную запись. Примеры:

''Host github.com''
	''HostName github.com''
	''User git''
	''IdentityFile ПОЛНЫЙ_ПУТЬ_К_ПЕРСОНАЛЬНОМУ_КЛЮЧУ''
	''IdentitiesOnly yes''

''Host myhoster.md''
	''HostName ПОЛНЫЙ_URL_СЕРВЕРА''
	''User ИМЯ_ЮЗЕРА''
	''IdentityFile ПОЛНЫЙ_ПУТЬ_К_ПЕРСОНАЛЬНОМУ_КЛЮЧУ''
	''IdentitiesOnly yes''

Начать целенаправленно бэкапить этот файл.

===== Перевести репозиторий на ssh =====

Обычно мы обращаемся к репозиториям через https, аутентифицируясь через логин/пароль. 

Проверить в каталоге репозитория:

''git remote -v''

Пример ответа, в котором видно, что репозиторий был клонирован по https:

''origin  https://github.com/testitquickly/bystro.linux.git (fetch)''
''origin  https://github.com/testitquickly/bystro.linux.git (push)''

Можно перейти на ssh тут же, в каталоге с репозиторием. Адрес для ssh можно получить на странице репозитория, но его шаблон простой и понятный:

''git remote set-url origin git@github.com:testitquickly/bystro.linux.git''

Проверить:

''git remote -v''

Ожидаемый ответ:

''origin  git@github.com:testitquickly/bystro.linux.git (fetch)''
''origin  git@github.com:testitquickly/bystro.linux.git (push)''
